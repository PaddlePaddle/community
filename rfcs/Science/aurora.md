## 1. 概述

### 1.1 相关背景

Microsoft Aurora 是地球系统预测基础模型。本提案将其 PyTorch 实现迁移到原生 Paddle，接入 PaddleScience，便于复用预训练参数、处理 ERA5 数据和执行监督微调。参考源码固定为 microsoft/aurora 的 `85dd3880683f0ac19aa8fe4386c5dcacfec99892`；保留原 MIT 版权和许可证。

### 1.2 功能目标

1. 迁移 Perceiver 编解码、3D Swin U-Net、变量 Patch Embedding、位置编码、归一化与自回归接口。
2. 实现原始权重数组到原生 `.pdparams` 的校验和布局转换；原生推理与训练不导入 Torch。
3. 通过 `AuroraArch` 对接字典输入输出，提供 `SupervisedConstraint`、`SupervisedValidator` 和 `Solver` 监督工作流。
4. 提供公开 ERA5 子集下载、数据转换、预训练推理、独立框架数值对齐及逐变量/层/时效指标。
5. 将实际验收范围和未解决的长时数值差异分别记录。

### 1.3 意义

为 PaddleScience 增加可复用官方预训练参数的气象基础模型，避免将 PyTorch 作为原生部署和训练的运行依赖。

## 2. PaddleScience 现状

本地核对的 develop 基线为 `aeba517c2718364ea6a9e2b43b569c1b5f0cd5bb`，已有多类气象模型和通用 Solver 接口，尚无本提案的 Aurora 模块。模型需显式处理变量、气压层、地理网格和历史时间，而不能直接使用其他气象模型的固定通道格式。

## 3. 目标调研

Aurora 通过变量 Patch Embedding 与 Perceiver 将不同物理变量和层编码为 token，使用 3D Swin U-Net 建模后解码输出。独立滚动会放大不同框架的 FP32 舍入差异，因此单次同输入前向与两框架独立长时预报应分别检查。迁移重点包括 native Linear 布局、注意力掩码与梯度、坐标池化舍入顺序、UTC 时间和混合浮点历史提升语义。

首期完整权重验收主要覆盖 AuroraPretrained（1,256,300,176 参数）；Small 用于结构和对齐调试。12h、HighRes、AirPollution、Wave、1.5 和集合变体代码已迁移，但不声称完成各自完整预训练参数验收。训练示例展示单对样本的工作流，不声称论文全量训练或统计预报技巧复现。

## 4. 设计思路与实现方案

- `ppsci/arch/aurora/`：原生模型、Batch/Metadata、归一化、滚动、独立随机流和权重适配。
- `AuroraArch`：地表键 `surf_<var>`、大气键 `atmos_<var>`，支持构造期静态场和元数据以及批输入覆盖。
- `examples/aurora/`：数据/权重下载、独立权重转换、推理、Hydra 配置驱动的 Solver 训练与评估、跨框架检查。
- `test/arch/test_aurora.py`：张量布局、梯度、权重加载、AMP、时区、滚动、数据对齐和指标验收回归。
- `docs/zh/examples/aurora.md` 与英文对应文档接入官网地球科学案例导航。

保留显式 FP32/FP64 注意力数值路径，低精度使用原生融合注意力。对独立窗口和解码器位置分批降低推理内存，保持每个位置内部的 token 和气压层。试验性 FP32 memory-efficient 优化尚未替换已验收默认路径。

## 5. 测试和验收的考量

采用固定官方权重和 ERA5 数据，关闭 TF32，Torch 与 Paddle 在独立环境执行。下述数值阈值为本项目预先固定的迁移标准，不声称为 PaddleScience 通用要求。

| 项目 | 项目阈值 | 当前观测最大值 |
| --- | --- | --- |
| 同输入前向标准化最大绝对误差 | 1e-4 | 4.21e-5 |
| 同输入前向变量相对 L2 | 1e-5 | 7.88e-7 |
| 连续三次训练更新的整体梯度相对 L2 | 1e-4 | 2.31e-5 |
| 更新后参数整体相对 L2 | 1e-5 | 9.35e-10 |
| 每变量/层/时效 RMSE 相对 Torch 差异 | 1% | 0.000943%，4,554 组通过 |

全参数训练对齐采用 17×32 空间采样和全部 13 气压层，不代表全分辨率训练。天气预报检查包含三个季节日期、最长 240 小时，另加原有两步案例。无气候态时不计算 ACC。

独立长时逐点检查仍使用 `rtol=atol=2e-4`，部分时效超差，必须明确保留 failed 状态，不能由 RMSE 通过替代。共享历史控制实验支持小数值差异随反馈放大的解释，但不能替代独立滚动验收。

另外验证官方 checkpoint SHA256、原生参数精确重载、CPU/GPU 回归、离线训练保存重载、wheel 内模型和许可证及官方 pre-commit。

## 6. 可行性分析和排期规划

- 已完成：主体迁移、原生权重转换、真实 ERA5 推理、三步全参数更新数值对齐和天气指标验收。
- 合入准备：标准配置与监督工作流、独立复现下载脚本、双语文档、质量及打包检查。
- 评审阶段：根据维护者意见调整接口、依赖和首期支持范围，再完成 CI 与审阅。
- 后续独立任务：长时逐点差异优化、更大日期集合、其他变体完整权重及全球训练验证。

本 RFC 在迁移原型形成后补充提交，请维护者评估首期合入范围及长期逐点对齐的验收要求。

## 7. 影响面

新增 Aurora 模块、架构注册、案例、测试与文档导航，不修改现有模型实现，不启用全局 `paddle.enable_compat()`。NetCDF 和下载依赖独立列于示例 requirements；不将 Torch 加入核心依赖。打包需包含上游 MIT 许可证。其他 Python/Paddle 组合尚需验证，不能由当前 Python 3.10/Paddle 3.4.0 测试结果推断其兼容性。
