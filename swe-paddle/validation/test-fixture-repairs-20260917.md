## 用例分类调整

- #50086：重复使用仍有效的 Scope 属于合法旧行为，改为 P2P；失效 Scope 不可复用仍是 F2P。
- #53534：原代码已能明确拒绝 dict，取消未约定的异常类型后，该项归为 P2P；NumPy 1.24 嵌套 Tensor 转换仍是 F2P。
- #78452：通过实际反序列化入口检查后，原代码已经能够拒绝的危险对象归为 P2P；缺少私有函数名不再造成虚假的 F2P。

## 验证方法和边界

1. 使用每题固定的 base commit，应用本 PR 的 tests/test.patch。逐项确认 F2P 失败、P2P 通过。
2. 在独立参考验证环境应用该题原有 solution/code.patch，确认同一套测试全部通过。
3. 在另一个独立环境重放已有候选答案，注入完全相同的测试，确认全部预期用例均通过。候选环境不含参考修复。
4. 检查补丁可应用、Python 语法及逐项结果。运行使用 CPU、关闭网络、只读源码和测试目录，无宿主目录挂载。

轻量测试执行待测 checkout 中的函数、属性或 C++ 片段，并仅模拟外部依赖。#59127、#78452、#78522 使用已验证的兼容 CPU 运行库，待测 Python 实现来自各自 checkout。它们没有重新完整编译每题 Paddle，不能据此声称覆盖所有运行模式。镜像、运行器、源码清单、测试及原生库摘要见同目录 JSON。

复验请按各题 environment/README.md 准备运行环境，并执行 tests/test.sh；须确认实际加载了应用补丁后的代码。#59127 沿用脚本排除 test_with_pir_api 的范围，#78522 沿用脚本指定的端口回归用例。测试标识和修订后的 F2P/P2P 列表见 [验证记录](test-fixture-repairs-20260917.json)。
