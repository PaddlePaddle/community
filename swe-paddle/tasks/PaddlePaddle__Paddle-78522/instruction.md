# 优化分布式 auto-tuner 的进程清理方式

## 详细描述

分布式 auto-tuner 在尝试下一组配置前，会清理仍在占用设备的残留进程。目前这一步通过拼接 PID 并执行系统 `kill` 命令完成。

这种方式存在两个问题：一是拼接并执行 Shell 命令存在命令注入风险；二是每次清理都需要额外启动 Shell 进程，带来不必要的系统开销。

同时，系统返回的 PID 列表可能包含空值、非数字内容或当前进程自身。待清理的进程也可能已经退出，或者当前用户没有权限终止该进程。遇到这些情况时，清理逻辑不应导致 auto-tuner 中断。

需要改用 Python 原生的进程终止接口，并补充 PID 检查和异常处理，使进程清理更加安全、轻量和稳定。

## 验收说明

* 不再通过拼接并执行 Shell 命令清理进程，改用 Python 原生接口。
* 忽略空值、非数字 PID 和当前进程自身，只清理有效的目标进程。
* 目标进程已经退出或当前用户没有终止权限时，不抛出未处理异常，也不中断后续 auto-tuner 流程。

## 技术要求

* 熟悉 Python 进程管理和信号处理。
* 熟悉 PaddlePaddle 分布式 launch 与 auto-tuner 流程。
