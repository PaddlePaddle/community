# 修复 `paddle.load()` 无法读取 dataclass 配置的问题

## 详细描述

有些模型文件除了参数之外，还会保存训练配置、模型配置等 Python 对象。这些配置经常使用 dataclass 或普通配置类来定义。

目前，这类文件虽然可以通过 `paddle.save()` 保存，但使用 `paddle.load()` 读取时会被安全加载机制拒绝，导致模型或训练状态无法恢复。

需要让 `paddle.load()` 能够正常读取不包含危险序列化行为的普通配置类和 dataclass。与此同时，加载过程原有的安全限制不能被放宽：如果对象自定义了可能在反序列化时执行代码或修改状态的特殊方法，仍然必须拒绝加载。

配置对象出现在字典、列表或其他模型数据结构中时，也应保持原来的对象内容，不影响其中 Tensor、NumPy 数组等已有数据的处理。

## 验收说明

- `paddle.load()` 可以读取由普通配置类或 dataclass 保存的安全对象，并保留其字段值。
- 配置对象嵌套在模型数据结构中时能够正常保留，其他已有数据仍按原逻辑处理。
- 定义了危险 pickle 特殊方法的类仍然被拒绝，已有白名单类型和安全模型文件继续正常加载。

## 技术要求

- 熟悉 Python 对象序列化与反序列化。
- 了解 dataclass 和普通 Python 类。
- 了解 Paddle 的模型保存、加载及安全校验。
