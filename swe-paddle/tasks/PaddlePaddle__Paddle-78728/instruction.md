# 为 Fleet recompute 增加可查询的执行上下文

## 详细描述

Fleet 的 recompute 会在前向流程中再次执行用户函数，但当前没有公开方式让该函数及其下游逻辑判断自己是否处于 recompute 调用中。这会使日志、计数或其他只应在普通前向执行一次的 Python 逻辑无法安全地区分两种执行阶段。

需要提供一个可查询的 recompute 状态，并将它接入现有 recompute 调用。该状态在 recompute 执行期间应为真，在调用结束后恢复为假；异常不能泄漏状态，并发线程之间也不能互相影响。现有 recompute 的返回值、梯度和训练步骤行为应保持一致。

## 验收说明

- 普通执行期间查询结果为假，recompute 包裹的调用期间为真。
- 状态接口应同时支持现有调用路径所需的装饰行为和上下文管理行为。
- 正常返回或抛出异常后，状态都应恢复。
- 一个线程中的 recompute 状态不能影响其他线程。
- recompute 与普通执行应产生一致的损失和梯度，完整训练步骤仍可更新参数。

## 技术要求

- 熟悉 Python 上下文管理器与装饰器语义
- 熟悉线程局部状态与异常安全清理
- 熟悉 Paddle Fleet recompute 的前向、反向和公开 API 导出
